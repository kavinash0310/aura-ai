# Local development

## Requirements

- Windows 10/11 with PowerShell.
- JDK 21.
- Docker Desktop with Compose.
- Maven 3.9 or later for local Java builds.
- Python 3.12 or later and uv 0.13.6 for local AI-service tests.
- Node.js 22 if developing the web workspace outside its container.
- Git.

## Configuration and startup

1. Copy .env.example to .env.
2. Replace placeholder DB, API, and internal AI service secrets with separate unique random values of at least 24 characters.
3. Keep .env untracked; never paste actual secrets into issues or logs.
   `AURA_ALLOWED_BROWSER_ORIGINS` defaults to `http://127.0.0.1:3000,http://localhost:3000`. If you serve the UI from another local origin, add that exact origin to the comma-separated list; do not use a wildcard. The API rejects browser requests marked as cross-site. Command-line clients without `Origin` or Fetch Metadata headers can still call the authenticated API.
4. Public GDELT news and Bluesky post search are enabled by default and require no key or account credentials. Add your own `AURA_BRAVE_API_KEY` to `.env` for Brave's web/news/discussion search; Automatic uses one provider (Brave first, then GDELT, then Bluesky), while All configured sources sends the query to each enabled provider. Set `AURA_GDELT_ENABLED=false` or `AURA_BLUESKY_ENABLED=false` to disable either provider. Only an explicitly started search sends its query; Brave may have quotas or charges under the owner's account. AURA records each provider outcome and commits each successful provider's rows with that outcome. If a search is interrupted by a backend restart, startup recovery keeps completed provider rows, marks the active run interrupted and later runs skipped, and does not retry. Bluesky search returns public posts and does not apply the country filter.
5. `AURA_NVD_API_KEY` is optional. The workspace requests one exact CVE from NVD only after you click “Load NVD details”; the optional key is sent in a header. No request runs automatically. The NVD response is cached in memory for six hours, up to 500 CVEs, and is not persisted.
6. Start with `docker compose up --build`.
7. Open the workspace at 127.0.0.1:3000. Enter the local Basic Auth credentials from `.env`; they remain in page memory and clear on reload or disconnect. Recent briefs can be reopened from the sidebar; deleting a brief removes its saved source rows.
8. Spring API binds to 127.0.0.1:8080. GET `/api/v1/health` is public; other routes use local HTTP Basic credentials. The web container proxies `/api` requests to Spring on the internal Compose network.
9. AI service binds to 127.0.0.1:8001. GET `/api/v1/health` is public and reports service identity only. The report, claim-comparison, and query-plan routes are internal-token protected; they are disabled unless the local Ollama provider is configured.
10. Optional local report and claim-comparison setup: install Ollama and at least one local model; set `AURA_AI_MODEL_PROVIDER=ollama`, `AURA_AI_OLLAMA_MODEL` to the installed name, and `AURA_AI_OLLAMA_BASE_URL` to the local Ollama origin. Generate a separate random `AURA_AI_INTERNAL_TOKEN`. Keep the model endpoint reachable only from trusted local services. No request goes to Ollama until the owner clicks Report, Compare claim, or Suggest with local AI. Query-angle generation sends only the topic to Ollama and does not search public providers. AURA sends the selected query/claim, source titles, URLs, and provider snippets for up to 20 checked sources; the first 20 visible sources are checked by default. It does not send document-library text or page snapshots from the separate Read page action.
11. Direct API: create a research job, explicitly call its `/search` route, then use `/sources` filters, `/report` with selected source IDs, or `/export?format=json|csv|md`. See the API contract for examples and limits.
12. The workspace's Cyber intelligence section accepts one to 25 exact CVE IDs or a CycloneDX 1.3–1.7 / SPDX 2.3 JSON SBOM or SARIF 2.1.0 report up to 2 MB. For an SBOM, AURA resolves only declared component/package references and enriches only CVE IDs already listed in the file; it does not infer CVEs from package metadata. For SARIF, AURA counts results but recognizes CVEs only from exact result rule IDs (or indexed driver rules), never from messages or file paths. For SPDX, only an exact CVE ID or NVD CVE-detail URL inside a SECURITY/advisory external reference is recognized; AURA does not fetch that URL. SARIF source paths and messages are not displayed or sent to providers. AURA downloads the CISA KEV catalog and sends only those CVE IDs to FIRST EPSS. Explicit “Load OSV advisory” and “Load GitHub advisories” clicks each send one exact CVE ID to the selected public provider; the SBOM file and package inventory are never included. After an explicit OSV request from an SBOM finding, AURA compares advisory and inventory PURLs locally, then compares exact affected-version strings for any ecosystem and complete npm SemVer 2 ranges when supported; other ecosystem ranges remain not assessed. Click “Load NVD details” on a CVE to request its bounded NVD record; the uploaded file itself is never sent to NVD, OSV, or GitHub. Results can be downloaded as JSON or CSV; uploads and lookup results are not stored. The CISA, NVD, OSV, and GitHub caches are memory-only and last six hours; NVD, OSV, and GitHub retain at most 500 CVE records each. A Brave search key is optional, and an NVD key is optional for the NVD provider action.
13. In Documents, import UTF-8 `.txt` or `.md` files, or text-based `.pdf` files, up to 1 MB. PDFs are capped at 100 pages and 250,000 extracted characters; scanned PDFs are rejected because OCR is not enabled. Search uses PostgreSQL's local full-text index plus an exact-phrase check and returns page citations for PDF matches. AURA stores only normalized/extracted text; the original PDF bytes are not retained. PDF downloads use an `.extracted.txt` filename. Documents remain local, are not sent to providers or models, and can be explicitly deleted.
14. Stop with `docker compose down`. Use `docker compose down -v` only when you intend to delete the local database volume.
15. Verify Java with `mvn -f backend/pom.xml verify`.
16. For frontend checks, change to `web` and run `npm ci`, `npm test`, then `npm run build`.
17. For Python checks, change into `ai-service` and run `uv sync --locked --all-groups`, `uv run pytest`, and `uv run ruff check src tests`.
18. Back up or restore the local PostgreSQL data with the PowerShell scripts in [`DATABASE-BACKUP-RESTORE.md`](DATABASE-BACKUP-RESTORE.md). A restore replaces the current database and needs the explicit `-ConfirmRestore` switch.

## Useful commands

- Service status: docker compose ps
- API logs: docker compose logs -f api
- AI-service logs: docker compose logs -f ai
- Database logs: docker compose logs -f db
- Create a verified database backup: `pwsh -NoProfile -File .\scripts\Backup-AuraDatabase.ps1`

## Limits

Basic Auth is development-only. Do not port-forward or publish the services. Search recovery assumes a single backend instance; do not horizontally scale this local configuration. Search sends an explicit query to the selected Brave, GDELT, and/or Bluesky provider(s), but does not fetch links automatically. Read page is a separate authenticated action for one source already saved in a brief: public HTTPS on port 443, public IPv4 only, two same-host redirects at most, one active read, 1 MB response and 100,000-character text caps, short DNS/connect/response timeouts, and a hard 20-second total deadline. It uses no cookies, login, compression, or retries. JavaScript is not run; page text is not saved or sent to Ollama. A metadata-only audit records each attempt (status, timestamps, hash/count/truncation or stable failure code) and is removed with its source or brief; “Read history” displays it without page text. Use its exact-phrase finder in the browser to inspect up to 200 matches and download excerpts with character offsets; those searches stay local. GDELT searches indexed public news over at most three months. Bluesky search uses the official public AppView and returns bounded public posts without account or private-feed access; it does not apply country filters. Saved results include provider provenance and can be filtered by provider; the provider run summary marks partial results and lists failure or skip codes. A report action sends only the selected saved result metadata and snippets to the explicitly configured local Ollama endpoint; it never falls back to a hosted model. Explicit vulnerability lookups read the CISA KEV catalog and send only submitted CVE IDs to FIRST EPSS; NVD receives exact CVE IDs only after a separate per-item or bounded batch click. SBOM and SARIF uploads are bounded to 2 MB, parsed in memory, and not persisted. Research documents are stored in PostgreSQL after explicit upload and remain local to this instance. Report citations are checked for source-ID membership but not semantic support. Vulnerability data does not establish whether installed assets are affected.

Database backups include all persisted research metadata, source snippets, provider audits, document text, and security audit records. They do not contain the original PDF bytes (which AURA does not retain). The backup directory is ignored by Git, but is not encrypted automatically; use an encrypted disk or encrypted storage and protect backup files like the original database. See the backup/restore runbook for integrity checks and restore behavior.

## Verification rule

Verification on 2026-11-08: GitHub Actions passed both push and pull-request workflows on commit `5e9bbb4` (backend, AI/Ruff, web, and Compose). The backend suite ran 47 tests with 0 failures; all 4 CI jobs passed. Frontend tests passed (10), as did TypeScript checking and the production build. Maven is unavailable in the current shell, so Java verification was performed by CI. Basic Auth is loopback development only. An authenticated explicit search sends a query to the selected provider or providers; uploaded files are not sent to search. Bluesky uses public post search only, applies no country filter, and does not connect to accounts. Saved Bluesky text is a local snapshot until the owner deletes the brief; AURA does not synchronize later remote post edits/deletions. The local model receives selected provider snippets only after an explicit report request; uploaded documents are excluded. Reports from partial searches include an explicit missing-provider coverage note, but citations are checked for source-ID membership rather than semantic support. FIRST receives exact CVE IDs only after authenticated lookup; AURA downloads CISA's catalog and matches locally. NVD receives exact CVE IDs only after an explicit per-item or batch request. Text/Markdown files are stored after explicit authenticated upload and searched locally. SBOM uploads are parsed in memory and only declared CVEs are submitted for KEV/EPSS enrichment; NVD detail is requested separately. Search results are partial and links are not fetched automatically; the separate page reader requires an explicit action and is restricted to one selected saved source. CVE and SBOM lookups are not asset discovery, vulnerability scanning, or a complete risk assessment.
